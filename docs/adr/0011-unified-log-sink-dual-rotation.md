# 0011 — shell.log 单写者合并与按天/大小双触发轮转归档

状态：Accepted（2026-10-20）

## 背景

`shell.log` 原本有 N+1 个互不知情的写者：1 个进程级 console tee（逐行同步）+ 每个 profile 服务面各一份 `createLogSink`（100ms 攒批），共写同一文件、各自记账。轮转只有「单文件 10MB×5 份」一档（`log-sink.ts` 的 `.1..4` 就地改名），时间维度轮转、保留、总量、归档全部为零；两套记账互相挤掉历史份，时间线不可信。页面 webview 日志只有 warn/error 镜像，relay 中继日志零轮转。

## 决策

1. **进程级唯一 sink + 进程级级别持有者**：tee 与全部 per-profile 服务面 sink 合并引用同一个日志内核 sink；级别（debug/info/warn/error）存进程级持有者，设置保存时同步——热切换不依赖各面各自的 `liveSettings`。
2. **双触发轮转**：跨天首写轮转 + 单文件超 10MB 即时轮转，先到先转。轮转产物 gzip 压缩进 `$DSH_HOME/logs/archive/`，命名 `<源词干>-<内容起始日 YYYYMMDD>-<当日序号>.log.gz`——用**内容日**（该份首行所属日）而非轮转时刻命名，跨天静默期产出的份不会错天。
3. **活跃文件契约不变**：`$DSH_HOME/shell.log`、`dsh-desktop-webview.log`、`shell-relay.log` 的路径与文件名是红线，升级后既有 `tail` 习惯照旧；轮转 = 活跃文件原子改名后新建续写。
4. **保留清理**：保留天数（默认 14）与总大小（默认 200MB）双阈值，先到先删最旧归档；只扫归档目录，天数阈值不作用于活跃文件。

## 取舍

- 单写者意味着 tee 不再自己逐行 `appendFileSync`，console 镜像到 stdout 的行为保留但写盘收口——换来行序稳定与「历史份不再被挤掉」。
- 轮转不再维护 `.1..4` 就地副本：升级时启动一次性把遗留 `.1..4` 压缩迁入归档目录，避免双轨长期并存。
- 归档压缩（gzip）而非原样存放：CPU 换磁盘（日志文本压缩比高），且归档份天然不可被误 tail。

## 后果

- 日志时间线可信：同一文件一个写者、一份记账；`rotated` 语义重定义为「归档目录中该源的份数」。
- 写/转/删失败不再 `catch {}`：按去抖上报进壳日志与诊断快照 `logs.health`（详见 #224 Decision 9）。
- `log-sink.ts` 退出主链路，仅存测试引用，后续可删。
