# 0012 — 日志管理命令不进远程/访客白名单

状态：Accepted（2026-10-20）

## 背景

统一日志管理新增三个 RPC 命令：`list_log_files` / `export_log_range` / `clear_logs`。壳的命令面有两张视图授权白名单（`view-grant.ts` 的 `GUEST_ALLOWED_COMMANDS` 与 `REMOTE_ALLOWED_COMMANDS`），进名单 = 该通道可直接调用。日志内容天然敏感：会话文本、token 痕迹、文件系统路径都在里面，而「导出日志」与「清空日志」更是直接的文件系统副作用（写 tar.gz、删归档、截断活跃文件）。

## 决策

三个日志命令**显式不进**两张白名单：仅本地面板（受 token 准入的 loopback 页面）可调用。`view-grant` 契约测试为每个命令补「GUEST 调用即拒 / REMOTE 调用即拒」的负例，防止后续有人顺手加白名单时无声漂移——漏同步要走 CI 红，不走静默。

## 取舍

- 手机端 / 远程访问用户暂时不能远程导出或清理日志：排障动作需要回到本机做。换来的是日志面不进入任何弱信任通道的可达面，与「日志含敏感内容」的默认立场一致。
- 「列出日志清单」看似只读，同样不进名单：清单暴露磁盘布局与文件名规律，且三命令同进退，规则简单过「只读的进、有副作用的不进」。

## 后果

- 契约同步锚是 `contracts/` 的 Commands 接口与 `COMMAND_NAMES` 运行时清单；`view-grant` 白名单的负例测试与命令清单契约测试共同钉住命令面。
- 若未来要做「远程导出脱敏日志」，须新立决策：脱敏管线 + 独立命令 + 显式白名单条目，不复用本组命令。
