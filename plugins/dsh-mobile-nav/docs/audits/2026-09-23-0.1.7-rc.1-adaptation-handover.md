### 1.2 怎么登进 `127.0.0.1:3080`

- `?token=` 是**进程内 launch token**（`browser-auth.ts` 的 `processLaunchToken`，WeakMap、不落盘），启动日志里被 app 打成 `token=***` —— **拿不回来**，只能重启 `dsh web` 看新打印的 URL。
- cookie 走的不是它，而是**持久化签名密钥**：`~/.dsh/.credentials.yaml` → `client-connection/browser-session.payload.secret`（32B base64url）。算法（`packages/client/connection/src/browser-auth.ts`）：
  - name = `dsh-auth-` + `b64url(sha256(authority))`，authority = Host 头（`127.0.0.1:3080`）
  - value = `v1.` + `b64url(JSON{version:1,authority,issuedAt,expiresAt})` + `.` + `b64url(hmac_sha256(secret, body))`
  - `expiresAt - issuedAt ≤ 30 天`
- 本次**店主明确授权**用密钥铸一次 cookie 取证（仓库规矩是「先问店主，不自己铸」）；用完已删。CDP 侧用 `Network.setCookie`（带 `httpOnly:true`）+ `Network.setCacheDisabled`。

## 2. 第 1 处：hero 工作区 chip「再点关不掉」

**症状**：点 chip 打开工作区列表后，再点 chip 关不掉（列表原地不动＝又开一次）。

**根因（两侧源码）**：宿主 chip 自己是正常 toggle（`ui-conversation` `ConversationContent.tsx`：`onClick: () => setPickerOpen(o => !o)`），但 `ui-workspace` 的 `WorkspacePickFlow` 把菜单开成 `<Menu anchor={null} portal getAnchorRect={…}>`；`anchor={null}` ⇒ Menu 的 `rootRef` 是**空 span**，chip 在 Menu 子树之外，而 `ui-primitives/Menu.tsx` 的关闭判定只豁免 `rootRef`/`listRef`。第二击顺序变成「pointerdown 被判外部点击 → 关；click 到 chip → 又翻回开」。

**旁证**：同一行的「预设」触发器传 `anchor={<button/>}`（在 rootRef 内），**没有**这个毛病——同一份 Menu，两种接线。

**改法**：新增 `src/client/effects/workspace-chip-toggle.ts`（`installMobileEffect` 门控，桌面零介入）：
- `pointerdown` **捕获**：chip 自报 `aria-expanded="true"` 且宿主 portal 菜单（`[role="menu"]`）在场 → 记下这一击；
- `click` **捕获**：同一 chip → `stopPropagation()`（React 挂在 root 容器上的 onClick 不再执行，宿主那次关闭成为唯一结果）；
- 菜单本来关着（第一击开启路径）完全不介入。

**两条不能改的判据**：
1. 选择器必须 `[class*="heroWorkspaceRow"] > button[aria-haspopup="menu"]` —— **直接子**是关键，预设触发器在 Menu 的 anchor span 里，吞它的 click 会让它的菜单关不掉。
2. 开态必须在 `pointerdown` 阶段读 `aria-expanded`，**不要到 click 再读 DOM**：React 18 对「原生 listener 里的 setState」是 NormalPriority 调度（MessageChannel 宏任务），click 时 portal 可能还没卸载，读到的是未冲刷的旧树。

**被否决**：补发合成 `Escape`（会打到插件自己的抽屉关闭 + 宿主 modal 的 document 级监听）；补发合成 `pointerdown`（同理 blast radius）。

**真机 A/B（390×844，真浏览器打真宿主）**：

| bundle | 第一击 | 第二击 | 菜单 |
| --- | --- | --- | --- |
| 原产物 `78c82874…` | 打开 | **仍开着（bug 复现）** | 仍挂载 |
| 修复后 `d6ffa47c…` | 打开 | **关上** | 已卸载 |

回归锚：`tests/workspace-chip-toggle.test.ts`（6 条：选择器/捕获阶段/开态读法/唯一 stopPropagation/dispose/入口武装）。

## 3. 第 2 处：全屏侧边栏面板把插件浮层压在下面

**症状**：打开 0.1.7 的全屏右侧边栏面板（终端 / 文件 / 预览 / 浏览器 tab）后，插件的悬浮球 FAB（面板占住主区后**唯一**的返回/抽屉入口）点不到；门户进 AppFrame overlayLayer 的弹层同样在它下面。

**根因**：宿主在 fullscreen 档把 `--dsh-dockkit-dock-layer` 设成 **40**（`.panel[data-sidebar-right-panel='fullscreen']`），dockkit 单元拿 z 40；而宿主 AppFrame `overlayLayer` 只有 **20**、本插件 FAB 只有 **21**。宿主在桌面是有意的（fullscreen 面板 > frame overlays），但手机上 FAB 是唯一入口 ⇒ 全断。

**改法**：`src/client/styles/base.css.ts` 的 mobile「popover band」节加同形 gate：

```css
body:has([data-sidebar-right-open][data-sidebar-right-panel="fullscreen"]) [data-mobile-nav="fab"] { z-index: 55 !important; }
body:has([data-sidebar-right-open][data-sidebar-right-panel="fullscreen"]) [class*="_overlayLayer"] { z-index: 1400 !important; }
```

**三条不能改的判据**：
1. **门必须带 `[data-sidebar-right-open]`**：`data-sidebar-right-panel="fullscreen"` 是展示档、面板关着也在（实测），只按它会把 band 常驻抬高 → FAB 会浮在打开的抽屉之上。
2. FAB 落 **55**（本插件「抽屉之下」带）：遮罩 1250 / 抽屉 1300 照旧盖住它，不回退 09-13 遮挡事故。
3. overlayLayer 用 **1400**（与抽屉 gate 同值）：两条 gate 同时命中时值相同，不会出现「右侧栏开着反而把层压到抽屉之下」。

**被否决**：FAB 抬 1400（浮在打开抽屉上）；只抬 overlayLayer 不抬 FAB（FAB 是 frame 子节点、不在该层里，实测 `fabChain[0] = pI_x6G_frame`）；降抽屉/遮罩 z（09-13 全黑事故）；逐面板打补丁。

**真机实测（390×844）**：

| 状态 | FAB z | 命中测试 | tap 结果 | overlayLayer z |
| --- | --- | --- | --- | --- |
| 面板关 | 21 | 命中自身 | — | 20 |
| 面板开（修复前） | 21 | **命中面板子节点** | **抽屉不开** | 20 |
| 面板开（修复后） | **55** | 命中自身 | **抽屉打开**（Escape 可关） | **1400** |

回归锚：`tests/overlay-layer-band.test.ts`（+3 条：FAB 带值区间、overlayLayer 同值、门必须含 open 属性）。
