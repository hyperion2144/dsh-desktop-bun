# 插件市场卡片图片横向滚动与自适应设计

日期：2026-08-22

## 问题

最新版插件市场卡片的图片集合使用 `cardShots` 类名片段。当前移动端兼容 CSS 已让图片集合横向滚动，但直接子项固定为 `180px`，导致手机上图片过小，且不同宽高比的图片无法充分使用卡片可用宽度。

## 目标

在移动端插件市场卡片中：

- 多张图片保持单行排列，并可通过横向滚动查看全部图片。
- 每张图片项按卡片内容区自适应宽度；手机上默认接近一张占满卡片，平板上不无限放大。
- 图片按原始宽高比显示，不拉伸、不裁切。
- 规则兼容最新版市场 UI 的 CSS Module 类名变化，不依赖完整哈希类名。
- 桌面视口（≥1024px）保持插件原始布局，不产生任何影响。

## 非目标

- 不修改 dshmarket 或其他第三方包源码。
- 不新增运行时 DOM 重排、MutationObserver 或 React 组件。
- 不改变卡片文本、标签、安装操作和市场导航布局。
- 不实现点击图片放大或独立图片查看器。

## 设计

### 样式边界

在 `src/client/styles/compat.css.ts` 的移动端兼容样式中继续使用：

```css
[data-mobile-nav="frame"] [class*="cardShots"]
```

该选择器同时满足两项约束：`cardShots` 作为第三方 CSS Module 的稳定语义片段识别图片集合；`data-mobile-nav="frame"` 将覆盖限制在插件已经确认的移动端框架内。现有 `@media (max-width: 1023px)` 外层保持不变，桌面端不加载这些规则。

### 图片集合

图片集合使用横向滚动窗口：

- `display: flex`
- `flex-wrap: nowrap`
- `overflow-x: auto`
- 允许触摸滚动，并使用细滚动条
- `min-width: 0`、`width/max-width: 100%`，避免反向撑大卡片
- 保留小的纵向内边距和图片间距

### 图片项和媒体

每个直接子项使用不可收缩的响应式宽度：

- `flex: 0 0 min(100%, 420px)`，让手机端单项占满可用宽度，同时限制平板端最大宽度。
- `width: min(100%, 420px)`、`max-width: 100%`，防止子项突破容器。
- `height: auto`。

子项内的图片或媒体元素使用：

- `display: block`
- `width: 100%`
- `height: auto`
- `max-width: 100%`
- `object-fit: contain`

这样横向滚动的单位是完整图片项；图片本身按原始比例适应项宽度。竖图会变高但不被裁切，宽图会占满可用宽度但不变形。

### 级联和兼容性

由于 dshmarket 可能通过后注入样式或行内样式设置图片尺寸，涉及第三方布局的声明保留 `!important`，但继续限定在市场图片容器和移动端框架选择器内。不得扩大到所有图片或所有 `role=img` 元素。

## 验证

1. 新增一个针对兼容 CSS 的可执行回归检查，覆盖：
   - 横向单行与滚动属性存在；
   - 不再使用固定 `180px` 图片项宽度；
   - 响应式宽度、媒体宽高自适应声明存在；
   - 选择器仍受移动端 frame 作用域约束。
2. 运行 `pnpm verify`。
3. 运行 `pnpm test:core`。
4. 运行 `pnpm build`，刷新提交的 `lib/` 产物。
5. 如本地 DSH Web profile 可用，在约 390px 和 768px 视口分别确认：图片集合可横向拖动、每张图完整可见且不变形；再在 ≥1024px 视口确认无移动端样式影响。

## 交付边界

源文件只修改 `src/client/styles/compat.css.ts` 和必要的测试文件；`lib/` 仅由 `pnpm build` 生成，不手工编辑。
